### [Q1. Largest Integer With Given Digit Sum](https://leetcode.com/problems/largest-integer-with-given-digit-sum/)
`貪心` `LC~est1200`

::: info 題意
給非負整數 $n$、$s$($n\le5$、$s\le100$)。回傳「**至多 $n$ 位**、數位和恰為 $s$」的最大整數;不存在則回 $-1$。

例:$n=2,s=9$ → $90$;$n=2,s=19$ → 兩位數最多湊到 $18$,回 $-1$;$n=5,s=0$ → 只有 $0$。
:::

::: tip 作法
兩件事想清楚就結束。

**何時無解**:$n$ 位最多湊出 $9n$,所以 $s>9n$ 直接 $-1$。

**怎麼最大**:先比位數、再比高位——所以位數要用滿 $n$ 位(少用一位只會更小),而且高位要盡量大。從最高位開始,每位塞 $\min(9,\ \text{剩餘的}\ s)$ 即可;把 $s$ 優先花在高位,低位自然補 $0$。

$s=0$ 是個看似邊界的情況:全部塞 $0$ 得到 $0$,而 $0$ 確實是「至多 $n$ 位、數位和為 $0$」的唯一非負整數,題目也是這樣要求的,不必特判。

```cpp
if (s > n * 9) return -1;
int res = 0;
while (n--) { res *= 10; res += min(9, s); s -= min(9, s); }   // 高位優先吃滿
return res;
```
:::

### [Q2. Aggregate Two Time Series](https://leetcode.com/problems/aggregate-two-time-series/)
`資料結構` `LC~est1400`

::: info 題意
兩個時間序列,元素為 `[timestamp, value]`,各自依 timestamp **嚴格遞增**。某 timestamp 在某序列**沒出現**時,它在該序列的值取「**下一個存在的 timestamp**」的值(往後看,不是沿用前一筆);後面沒有了就當 $0$。

對「在任一序列出現過」的每個 timestamp,把兩序列的值相加,依 timestamp 遞增輸出 `[timestamp, summedValue]`。

例:`s1=[[1,3],[4,1]]`、`s2=[[2,2],[5,2]]`:

| $t$ | s1 | 為什麼 | s2 | 為什麼 | 和 |
|---|---|---|---|---|---|
| 1 | 3 | 自己有 | 2 | 沒有 → 取 $t=2$ 的 2 | 5 |
| 2 | 1 | 沒有 → 取 $t=4$ 的 1 | 2 | 自己有 | 3 |
| 4 | 1 | 自己有 | 2 | 沒有 → 取 $t=5$ 的 2 | 3 |
| 5 | 0 | 沒有,**後面也沒了** | 2 | 自己有 | 2 |
:::

::: tip 作法
題目那段「取下一個可用 timestamp」描述得很繞,但翻成實作只有一句:**merge 兩個排序序列時,某側「還沒被消耗掉的第一筆」的值,就是該側的當前值**——因為它的 timestamp 必定 $\ge$ 目前處理的 $t$。指標走完了就是 $0$。

於是整題就是標準的雙指標 merge:每步取兩側 timestamp 的較小者當 $t$,兩側各讀自己指標當下的值相加。三個容易寫錯的地方:

- **先算和、再推指標**——反過來會把「自己這一筆」先跳掉;
- **兩邊 timestamp 相同時,兩個指標都要推進**。題目沒說 timestamp 不會重疊,三個範例也剛好沒示範,但這是合法且會發生的情況,而且反而是最單純的 case(兩邊各取自己的值);
- 迴圈條件是 `||` 不是 `&&`——一邊走完了另一邊還要繼續輸出(此時走完那側貢獻 $0$)。

```cpp
auto v1 = [&] { return p1 < (int)s1.size() ? s1[p1][1] : 0; };   // 指標當下的值
auto v2 = [&] { return p2 < (int)s2.size() ? s2[p2][1] : 0; };
while (p1 < (int)s1.size() || p2 < (int)s2.size()) {
    int t;                                                       // 兩側 timestamp 取 min
    if (p2 >= (int)s2.size())      t = s1[p1][0];                // 單側走完就取另一側
    else if (p1 >= (int)s1.size()) t = s2[p2][0];
    else                           t = min(s1[p1][0], s2[p2][0]);
    res.push_back({t, v1() + v2()});                             // 先算和
    if (p1 < (int)s1.size() && s1[p1][0] == t) p1++;             // 再推指標(相同 t 都推)
    if (p2 < (int)s2.size() && s2[p2][0] == t) p2++;
}
```
:::

### [Q3. Count Valid Sequences](https://leetcode.com/problems/count-valid-sequences/)
`組合計數` `容斥` `LC~est1600`

::: info 題意
給正整數 $n$、$k$($n\le5\times10^5$、$k\le n$)。**求**長度恰為 $k$ 的正整數序列中,總和為 $n$ 且**乘積為偶數**的個數,mod $10^9+7$。順序不同算不同(`[1,1,2]` 與 `[1,2,1]` 分開計)。

例:$n=5,k=3$ → 全部 $6$ 種拆法中,`[1,1,3]` 的三個排列乘積為奇,其餘 $3$ 種為偶 → 答案 $3$。
:::

::: tip 作法
「乘積為偶」$\iff$「至少一項是偶數」。**至少一個**的反面是**全部都不是**——而「每一項都是奇數」是個單一乾淨的形態,所以走補集,不必按「有幾個偶數」分 case。

**全體**:$n$ 拆成 $k$ 個正整數的有序拆法,隔板法得 $\binom{n-1}{k-1}$。

**全奇**:令 $a_i=2b_i+1\ (b_i\ge0)$,代入 $\sum a_i=n$ 得 $2\sum b_i+k=n$。所以**必須 $n-k$ 為偶**(合理:$k$ 個奇數的和與 $k$ 同奇偶,湊不出不同奇偶的 $n$);此時個數為「$\sum b_i=\frac{n-k}{2}$ 分給 $k$ 個非負變數」$=\binom{\frac{n-k}{2}+k-1}{k-1}$。

$$\text{答案}=\binom{n-1}{k-1}-\bigl[\,n\equiv k \pmod 2\,\bigr]\binom{\tfrac{n-k}{2}+k-1}{k-1}$$

$O(n)$ 預處理階乘與逆元後 $O(1)$ 回答。

```cpp
ll all = C(n - 1, k - 1);                          // 隔板:n 拆 k 個正整數
ll odd = 0;
if ((n - k) % 2 == 0)                              // 奇偶對上才有全奇解
    odd = C((n - k) / 2 + k - 1, k - 1);           // a_i = 2b_i+1 後的非負分配
return (all - odd + mod) % mod;
```
:::

### [Q4. Minimum Cost Path with Alternating Directions III](https://leetcode.com/problems/minimum-cost-path-with-alternating-directions-iii/)
`最短路` `圖論` `LC~est2400`

::: info 題意
$m\times n$ 格子,從 $(0,0)$ 走到 $(m-1,n-1)$。**進入** $(i,j)$ 要付 $(i+1)(j+1)$,而且**每次進入都付**(走回頭路會重複付)。起點先付 $1$,之後動作編號從 $1$ 開始。

**奇數號動作**往右/下才合法,**偶數號**往左/上才合法;但四個方向隨時都能走,違規時多付**出發格**的 `penalty[i][j]`(不是目的地)。也可以原地等待,付 `penalty[i][j]`。每個動作(含等待)都讓編號 $+1$,所以奇偶必翻。

**求**到終點的最小總花費。$m,n\le10^5$ 但 $m\cdot n\le10^5$。

例:$m=n=2$、`penalty=[[5,3],[1,4]]` → 下到 $(1,0)$(動作 1 合法,付 $2$),再右到 $(1,1)$(動作 2 違規,付 $4+\text{penalty}[1][0]=5$)→ 總計 $1+2+5=8$。
:::

::: tip 作法
狀態很直觀:$(i,j,p)$,其中 $p$ 是**下一個動作編號的奇偶**;五種轉移(四方向 + 等待)每個都翻 $p$。邊權全部非負(進入費 $\ge1$、penalty $\ge0$),所以 **Dijkstra**。

真正該想清楚的是另一件事:**能不能只走右/下 + 等待,做成 DP?** 答案是不行,理由很漂亮——**左/上在偶數號動作是合法免罰的**,所以往回走一步等於「免費的翻奇偶手段」,還能順便換到 penalty 便宜的走廊。拿隨機測資對拍,只走右/下的 DP 在 22518 組中有 759 組算得比最佳解貴。

下圖是其中一個反例($4\times2$,格內數字是 penalty),最佳解 $24$:動作 ④(偶數號)**免費往左**切到第 0 欄,因為那裡 `penalty[2][0]=0`,讓後面那步違規往下不用付錢。

那改成 top-down 記憶化呢?也不行——依賴圖有環($(i,j,p)\to(i,j-1,p{\oplus}1)\to(i,j,p)$),找不到合法的計算順序;硬做就退化成反覆鬆弛到收斂(Bellman-Ford,$O(VE)$)。就算想按 $i+j$ 分層,複合移動「左+下」與「上+右」**不改變 $i+j$**,層內仍需最短路,一樣沒有 DAG 化。

**所以這題的 DP 就是 Dijkstra**——差別只在用什麼提供計算順序。有環的圖上,只有「距離由小到大」拿得到那個順序。$m\cdot n\le10^5$ 代表狀態才 $2\times10^5$、邊 $10^6$,那個 log 完全無感(本機極限測資 21ms)。

```cpp
// 狀態 (i,j,p),p = 下一個動作編號的奇偶(0 = 奇);每個動作都翻 p
if (i == m - 1 && j == n - 1) return c;             // 第一次彈出終點即最小
ll pe = penalty[i][j];                              // 罰金算「出發格」的
ll rd = p ? pe : 0, lu = p ? 0 : pe;                // 奇:右下免費;偶:左上免費
if (j + 1 < n) relax(i, j + 1, p ^ 1, c + fee(i, j + 1) + rd);
if (i + 1 < m) relax(i + 1, j, p ^ 1, c + fee(i + 1, j) + rd);
if (j > 0)     relax(i, j - 1, p ^ 1, c + fee(i, j - 1) + lu);
if (i > 0)     relax(i - 1, j, p ^ 1, c + fee(i - 1, j) + lu);
relax(i, j, p ^ 1, c + pe);                         // 等待:只付 penalty
```

順帶一提,實測最佳路徑的**倒退永遠只有一步**(從沒出現連續兩步),但同一條路徑上會反覆倒退十幾次——所以不是罕見角落,是常態行為。
:::
